为什么不建议用 IPv6 访问 Claude Code？分流场景稳定性指南

发布于 2026 年 10 月 22 日 · 阅读约 7 分钟 · 作者：Gutast AI 内容团队

这可能是大部分人都忽视掉的一个问题。如果你在用代理访问 Claude，这篇文章值得花三分钟看完。

很多用户的排查清单里有换节点、改 DNS、清缓存，唯独没有「检查 IPv6」这一项。但在「分流 + 代理」这个场景下，IPv6 恰恰是最常见的稳定性黑洞：它让你的流量悄悄绕开代理、让风控看到两个互相矛盾的出口、让「第一次请求特别慢」这种玄学问题反复出现。

先说结论

在「分流 + 代理」场景下，强烈建议关闭 IPv6，或者至少禁用 IPv6 解析。尤其是访问 Claude Code 这种 API 工具时，这几乎是稳定性优化的必做项。一行配置的成本，直接消灭一整类潜在问题。

一、核心问题：IPv6 很容易绕过你的代理规则

先说本质。你配的代理规则，大多数情况下只匹配 IPv4，或者 domain 匹配时只命中 A 记录。但 Anthropic 的服务同时有 A 记录（IPv4）和 AAAA 记录（IPv6）。

这意味着什么？

请求类型路径结果
IPv4 请求命中代理规则 → 走代理出口正常，符合预期
IPv6 请求没命中规则 → 本地直连出去绕过代理

结果就是：你以为流量走了代理，实际上 IPv6 那部分悄悄从本地网络直连出去了。代理日志里看不到，你自己也感知不到。

二、家宽 IPv6 的另一个坑：地址不轮换，段信誉连坐

市面上能买到的家宽 IP，绝大多数以 IPv4 作为主力出口。运营商会定期给你换一个新的 IPv4 动态地址。但 IPv6 呢？大部分运营商是不会自动轮换的。

听起来「稳定」是好事对吧？但反过来想：你的 IPv6 地址永远不变，意味着这个地址上所有「邻居」的行为都会影响到你。如果同一个 /48 段里有人做过不当操作，这个段的信誉就被拉低了，而你还在用它。

对 AI 服务来说，这等于把风控评估的主动权交给陌生人：你什么都没做错，但你的 IPv6 出口可能因为同段邻居的历史行为被标记为高风险。

三、关闭 IPv6 的 6 个实际好处

1. 避免分流失效、流量偷跑

这是最关键的一条。不关闭 IPv6 的话，Claude Code 的请求有一定概率直连（尤其在日本这种 IPv6 普及率高的环境下）。关闭之后，所有流量 100% 强制走你设定的代理规则，完全可控。

2. 解决「第一次慢、第二次快」的玄学问题

如果你遇到过这种情况——第一次请求特别慢，刷新一下就快了——本质上很可能是这样的：

  • 第一次：系统优先尝试 IPv6（直连或路径差）→ 超时；
  • 第二次：fallback 到 IPv4 → 走代理 → 快了。

关闭 IPv6 后路径唯一，不存在双栈竞争，不再抖动。改完之后可以用 IP 查询工具验证一下，看看你的出口是不是只剩 IPv4 了。

3. 避免 DNS 解析不一致

IPv6 环境下很容易出现一种情况：AAAA 记录走了本地运营商 DNS 解析，A 记录走了代理的 DNS。两边解析结果不一样，导致 IP 不一致、地区漂移（比如一会儿日本一会儿台湾）。关闭 IPv6 后只剩 IPv4，DNS 行为完全统一。

想检测你的 DNS 是否存在泄露？试试 DNS 泄露检测。

4. 降低风控风险

这一条非常关键。很多 AI 服务（包括 Claude）会综合判断你的 IP 区域、网络稳定性、ASN 等信息。如果你的 IPv4 走日本代理，IPv6 却从本地或者台湾出去，在平台眼里同一个用户的请求来源就「分裂」了。后果可能是验证变多、API 不稳定、甚至限速。关闭 IPv6 后出口单一，风控评估更干净。

另外，IPv6 环境下 WebRTC 也容易泄露真实 IP，建议用 WebRTC 泄露检测确认一下你的 UDP 出口是否正常。

5. 提升代理规则命中率

实际使用中，很多代理配置里的 domainStrategy 设的是 IPIfNonMatch。在 IPv6 可用的情况下，系统很容易直接走 AAAA 记录命中直连规则，完全绕过代理。关闭 IPv6 后，所有域名只解析 A 记录，规则命中率大幅提升。

6. 排查问题简单很多

工程上这点同样重要。不开 IPv6 的话，所有流量都是 IPv4，路径单一。排查问题的时候不用考虑 Happy Eyeballs 协议、双栈竞争、fallback 行为这些变量。出了问题，抓包看一条线就够了。

四、有没有坏处？

客观来说，关闭 IPv6 理论上有两个缺点：

  • IPv6 在某些线路上可能更快（比如日本部分运营商的 IPv6 优化线路）；
  • 极少数网站只支持 IPv6（现实中几乎遇不到）。

但对于你的场景——代理用户、分流复杂、追求稳定性——关闭 IPv6 的收益远大于代价。实测没有任何实际风险。

五、推荐做法

最推荐：代理层强制 IPv4，不用全局关闭

不用全局关闭 IPv6，但所有代理相关流量强制走 IPv4。在代理客户端里把 domainStrategy 设为 ForceIPv4 或 UseIPv4。

如果你不想折腾配置，也可以直接在系统层面关闭 IPv6：

系统层面关闭方法

Linux：

sysctl -w net.ipv6.conf.all.disable_ipv6=1

macOS：

# 系统偏好设置 → 网络 → 对应接口 → 详细信息 → TCP/IP
# 「配置 IPv6」选择「仅本地链路」（或用 networksetup 命令关闭）

Windows：

# 网络适配器属性 → 取消勾选「Internet 协议版本 6 (TCP/IPv6)」

路由器层面：在路由器管理界面关闭 IPv6 DHCP 分配，一劳永逸。

最省事：客户端配置文件加一行

如果你用的是代理客户端，最简单的方式是在配置文件里直接加一行：

# 严格关闭 IPv6
ipv6 = false

加上这一行之后，客户端会拒绝所有 IPv6 连接请求，强制所有流量走 IPv4。不需要改系统设置，不需要动路由器，重启客户端就生效。这是最低成本、最不容易出错的做法。

六、改完之后，先做一次检测

配置改动不能靠「感觉快了」来验证。用 Gutast AI 的 Claude IP 检测工具跑一遍：

  1. 出口 IP：确认直连与代理环境下都只剩 IPv4，且代理出口地区与你预期一致；
  2. DNS 泄露：确认解析走的是代理侧 DNS，而不是本地运营商；
  3. WebRTC 泄露：确认 UDP 出口没有暴露真实 IP。

三项全绿，才算真正把 IPv6 这条暗道堵死。

常见问题

Q：关闭 IPv6 会影响正常上网吗？

基本不会。绝大多数网站同时具备 A 记录和 AAAA 记录，关闭 IPv6 后走 IPv4 完全无感；只有极少数仅支持 IPv6 的站点会遇到，现实中几乎碰不到，真遇到临时打开即可。

Q：怎么确认出口已经只剩 IPv4？

配置完成后用 Claude IP 检测工具跑一次，分别核对直连与代理环境的出口 IP、DNS 解析与 WebRTC 泄露状态。如果结果里仍出现 IPv6 地址，说明客户端或系统层面还有一处没关干净。

Q：代理客户端里应该怎么设置？

把 domainStrategy 设为 ForceIPv4 或 UseIPv4，让所有代理相关域名只解析 A 记录；最省事的做法是在配置文件中加一行 ipv6 = false，客户端会拒绝所有 IPv6 连接请求，重启客户端即生效。

Q：为什么说家宽 IPv6 段风险高？

运营商会定期轮换家宽的 IPv4 动态地址，但 IPv6 地址大多长期不变。同一个 /48 段里只要有用户做过不当操作，整个段的信誉就会被拉低，而你的请求仍从这个段出去，风控评估会被连累。
