## 第一步不是学代码，是搞清楚环境

Claude Code 是跑在终端里的 AI 编程工具，安装本身不难，跟着官方文档复制粘贴命令就行。真正让我懵的是第一次启动时的连接报错。我一个词一个词地搜索，才发现新手栽跟头的地方大多不是「不会写代码」，而是网络环境：出口 IP 的类型、IPv6 连接问题、系统时区和 IP 所在地不一致……这些词我以前一个都没听过。

举个例子：我第一次跑 Claude Code 就卡在连接上，而且报错很玄学——有时候能连上，有时候死活连不上，重启也没用。折腾半天才发现是网络优先走了 IPv6，而代理环境对 IPv6 的支持并不稳定。这类问题在零基础人群里非常普遍，报错信息还特别劝退。后来是[这篇 IPv6 排查文章](https://www.gutast.com/blog/claude-code-ipv6-issue)救了我，对着一步步改就通了。

> **什么是环境风控（我的通俗理解）**：平台的风控系统会持续检查你的使用环境是否稳定——IP 是否经常大幅跳变、时区是否和 IP 所在地对得上、网络配置是否正常。环境不稳定，账号就可能被盯上。对新手来说，用之前先自查一遍，比出事之后再补救省心得多，就像写作业前先收拾好书桌。

## 这一节是全文最干的干货：风控到底在查什么

搜多了我发现，网上讲「环境风控」的文章基本都在喊口号：「IP 要干净」「时区要一致」，但没人解释为什么。我把零散的信息消化了一晚上，下面用我能听懂的话把它讲透。先给结论：

> **核心结论**：风控查的不是「你在哪」，而是「你像不像一个正常的、稳定的人」。位置本身不是问题，自相矛盾才是问题。风控的判定逻辑是「一致性」：你各个维度的环境信息，能不能拼出一个自洽的真实用户。

### 信号一：IP 类型——机房 IP 为什么天生可疑

IP 不只分国家，还分「出身」。你在家里电信宽带上网，用的是住宅 IP（Residential IP）；而买了台云服务器搭的网络出口，用的是机房 IP（Datacenter IP）。风控系统怎么区分？每个 IP 段都登记了归属组织，这个编号叫 ASN——家宽的 ASN 归电信、联通这类运营商，机房 IP 的 ASN 归阿里云、AWS 这类数据中心。查一下就知道。

为什么风控在意这个？想一想正常人的上网方式：家里 WiFi、公司网络、手机流量，全是住宅 IP。一个用户 24 小时从机房 IP 登录，说明什么？说明流量经过了数据中心中转——这是代理和共享网络的典型特征。机房 IP 本身不违规（程序员用云服务器天经地义），但它是「伪装环境」的高发地带，风控自然会多看一眼。对新手来说，能走家宽就别走机房线路，这是最省心的选择。

### 信号二：时区——不一致暴露的不是位置，是伪装痕迹

这一条最反直觉，我一开始也想错了。我以为风控是抓「人在中国」，后来才明白不是。Claude Code 每次请求都会带上系统环境信息，系统时区就是其中一项。于是问题来了：如果你的出口 IP 在美国，系统时区却写着 UTC+8（中国），这两条信息放在一起，等于主动告诉平台「我在用代理改位置」。平台生气的从来不是你在哪，而是你在撒谎。

所以「改系统时区」的本质不是掩饰位置，而是让环境自洽——让系统时区、IP 所在地、语言习惯这些信息讲同一个故事。具体怎么对、怎么改，[时区自查方法](https://www.gutast.com/blog/claude-code-timezone-risk-check)这篇讲得很细，我是照着改的。

### 信号三：IPv6——「时连时断」和「IP 跳变」的元凶

这是我最想讲透的一条，因为我在这上面耗了整整一晚上。现在家庭宽带基本都同时分配了 IPv4 和 IPv6 两套地址。当你的电脑要连一个网址时，系统会默认优先尝试 IPv6（这叫 Happy Eyeballs 机制）。问题在于：常见的代理工具往往只接管 IPv4 流量，IPv6 请求会绕过代理直接出去。

后果有两种：轻则目标服务不支持直连，时连时断；重则更可怕——一部分请求走了代理（比如出口显示美国），另一部分走了 IPv6 直连（暴露真实位置）。同一个账号，几分钟内从两个国家发起请求，这就是「IP 跳变」，是风控系统里权重最高的红灯之一，因为正常用户绝不会这样。解决办法要么在系统里关掉 IPv6，要么让代理工具完整接管 IPv6，总之保证所有流量走同一条路。

### 信号四：稳定性——风控是看长期表现的

最后一个信号最简单：别频繁换环境。今天用这个节点、明天换那个城市，风控视角里这就是「账号在异地流浪」，像被盗号了。我现在的原则是固定一条线路用到底，宁慢勿换。稳定性比速度重要得多。

## 我的四步自查流程（新手照抄版）

理解了原理，自查就不再是玄学。我把它整理成四步，每步都有明确的动作和判断标准：

1. **查出口 IP 的归属和类型**：确认是住宅 IP 还是机房 IP，归属地是否和预期一致——记下这个结果，这是你的「环境基线」；
2. **对比系统时区和 IP 所在地**：不一致就先把系统时区改对，让环境自洽（[时区自查方法](https://www.gutast.com/blog/claude-code-timezone-risk-check)）；
3. **确认 IPv6 是否会造成泄漏**：测一下 IPv6 是否真的通、代理是否接管了它，保证所有流量走同一条路；
4. **固定环境不再折腾**：节点固定、设备固定，改完之后观察几天，没有异常再开始正式使用。

前两步用命令就能查，复制粘贴就行：

```text
# 1. Check your public IP, org (ASN) and region
curl ipinfo.io

# 2. Check system timezone
# Windows:
tzutil /g
# macOS / Linux:
date +%Z

# 3. Test whether IPv6 actually works
ping -6 ipv6.test-ipv6.com
```

环境搞定之后，Claude Code 的上手体验顺滑了很多。结合我之前做小程序的经验，有三条心得先记下来：
