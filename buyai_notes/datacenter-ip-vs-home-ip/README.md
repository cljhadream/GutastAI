# 我的踩坑实录：为什么换了 IP 还是被认出来？搞懂机房 IP 和住宅 IP 的"出身"

> 本篇是「学爸学AI」系列第 03 篇 · [返回总目录](../README.md)

> 儿子凑过来问我："爸爸，IP 不就是一个号码吗？换一个不就行了？"为了回答他，我把 ASN、信誉库、行为分析这一整套查了一个晚上。结论是：风控看的从来不只是你住哪个门牌号，还有你这个门牌号住的是什么楼。

![学爸深夜研究 IP 出身，窗外居民楼与写字楼灯光对比](images/cover.webp)

大家好，我是学爸，不懂代码的普通爸爸，按周记录自己学 AI 编程的全过程。这个话题是后台被问得最多的：[环境自查](../claude-code-starter-notes-01/README.md)我也做了、[开工清单](../claude-code-first-day-checklist/README.md)也过了，怎么换了 IP 还是被断连、被风控盯上？这一篇把它讲透。

## 先给结论：风控查的不是"你的 IP 是多少"，是"你的 IP 是什么出身"

> **核心结论**：IP 地址像门牌号，ASN 像户口。门牌可以随便换，户口换不掉——而风控系统看的主要是户口。

我一开始也以为"换 IP"就是万能钥匙，被现实教育了两回才明白：**问题不在号码本身，在号码背后登记的那个组织**。

## IP 也有出身：ASN 到底是什么

每个 IP 段在互联网上都登记了归属组织，这个编号叫 ASN（自治域号码）。你家宽带的 IP，ASN 归电信、联通这类运营商；云服务器的 IP，ASN 归阿里云、AWS 这类数据中心。查询这件事对任何风控系统来说都是一瞬间的事——所以"你从哪种网络接入"基本是明牌。

自己查也只要一条命令，看输出里的 org 字段：

```text
# Check who your IP belongs to (look at the "org" field)
curl ipinfo.io
```

我的理解是这样：家宽像独栋住宅的门牌，一户一号；机房 IP 像写字楼里的房间，整栋楼共用一个物业、一个前台。风控分不清楼里哪个房间在干什么，但它一眼能看出"这人天天从写字楼登录"。

### 三种出身：住宅、机房，和最容易被忽略的第三种

- **住宅 IP**：家宽、手机流量，普通人正常的上网方式，出身最干净；
- **机房 IP**：云服务器、VPS 的 IP。程序员用云服务器天经地义，所以机房 IP 本身不违规，但它是"伪装环境"的高发地带，风控自然会多看一眼；
- **第三种：共享住宅 IP**——这是我后来才学到的坑。很多所谓"动态代理"用的就是它：出身栏填的是住宅，实际是几百个人轮着用的公共门牌，前科最多。看起来最像真的，往往最不干净。

## 换了 IP 为什么还会被认出来：三层判定

### 第一层：换 IP 不换出身

同一家服务商的 IP 池，换十个地址，ASN 还是同一家。这就是"机房里换房间"——物业没变，前台还认识你。如果你的线路本身出自机房段，换 IP 这件事在风控眼里约等于没发生。

### 第二层：信誉库的"前科"

风控公司维护着庞大的 IP 信誉库：一个 IP 段被滥用过——批量注册、恶意请求、共享账号扎堆——整段都会被记上一笔。你租到手的 VPS 地址，前任租客干过什么你不知道，账却可能记在你头上。这就是为什么同一个服务，有人用着没事，有人一上就异常：差的不是用法，是地址的历史。

### 第三层：行为对不上

出身干净、历史清白，还得像正常人一样行事：登录时间集中在你所在时区的白天、地点稳定不漂移、行为节奏像人。半夜三点高频请求、一小时内从两个国家出现——出身再好也会被重点关照。行为这一层，[上篇开工清单](../claude-code-first-day-checklist/README.md)里"给自己定预算、别瞎折腾"说的就是它。

## 我的三条选择原则（给边界）

1. **能走家宽和手机热点，就不走机房线路**：对零基础用户这是最省心的路，出身干净，行为也天然像正常人；
2. **必须用线路服务时，看两点**：IP 是不是独享、服务商会不会频繁给你换 IP。"独享 + 固定"比"住宅 + 共享"重要得多——共享住宅 IP 的前科池你完全不可控；
3. **换环境前后各测一次，记录基线**：知道自己平时长什么样，才知道异常长什么样。把每次测出的 IP 类型、归属地记在本子上，一周后你就能看懂自己的"环境曲线"。

> **新手心得**：记住一句话就够了——风控抓的不是"你在哪"，是"你像不像一个稳定、自洽的真人"。让环境讲同一个故事，比换一百个 IP 都管用。
